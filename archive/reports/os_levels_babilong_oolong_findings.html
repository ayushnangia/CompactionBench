The main mechanism

Why virtual context helps

For BABILong, the system extracts a clean event trace like Mary journeyed to the bathroom and ignores unrelated carrier prose like Mary Linden went to Didlum's shop.

The model no longer has to decide which page to search or which page to trust.

Why it does not solve everything

OOLONG is not just retrieval. It often requires counting, percentages, first/last spell lists, or aggregation across episodes.

Virtual context retrieves evidence, but it does not yet run a deterministic map-reduce/counting operator.

Important caveat about the 8k/24k/48k labels

The budget labels are best understood as resident-set targets, not perfectly enforced hard caps in this run. Large structured evidence items could exceed the nominal budget, especially for OOLONG event windows.

Observed average evidence tokens: virtual_8k ≈ 14k, virtual_24k ≈ 14.4k, virtual_48k ≈ 28.7k. This should be tightened before the next budget-sensitivity run.

What to build next

  1. Do not re-run baselines. Reuse fixed-panel full_context/grep results unless model/prompt/task set changes.
  2. Fix hard budget enforcement for virtual-context packets.
  3. Add page-fault retry: answer → verifier checks support → kernel loads more pages → retry.
  4. Add structured OOLONG operators: roll table extractor, spell table extractor, count/first/last/percentage functions.
  5. Run only new corrected virtual arms and merge with existing baselines offline.

Slack-ready summary

Ran an OS-level memory ladder on the fixed BABILong/OOLONG panel: 250 tasks × 6 arms = 1500 runs.
Best overall: transparent virtual context. It beat grep overall while using 0 tools: virtual_8k relaxed 39.6%, virtual_24k strict 24.8%, grep relaxed 37.2% / strict 20.8%.
Why: virtual context system-loads a clean evidence packet before the model answers. This helps BABILong by extracting concise event facts and avoiding carrier-novel false matches.
Limit: OOLONG is still hard because it needs real aggregation/counting, not just retrieval. Next step: add verifier-driven page faults and structured roll/spell table operators.
