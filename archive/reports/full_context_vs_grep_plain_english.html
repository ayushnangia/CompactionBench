Does grep beat full context?

Short answer: we have not shown that. What we have shown is simpler and still important: searching the original file can beat an agent’s squeezed-down chat memory.

plain English no hidden trick 100-task replication done next step: clean full-context control
The clean verdict

Yes: Grep can beat the agent’s long chat memory after the chat has been compressed.

No: We should not claim that grep beats a truly lossless full-context prompt. That still needs a direct test.

Why this matters

If the model really has the whole source in front of it, full context should be very strong.

But a long agent chat is different. Older messages may get squeezed into a short summary. At that point, the model no longer has the original source word-for-word.

The three things people are mixing up

1

True full context

The original text is still sitting inside the model’s active view, word-for-word.

This is the clean “full context should work” case.

2

Agent chat memory

We feed the text to Codex over many messages. Later, Codex may squeeze old messages into a shorter note.

This is not the same as true full context.

3

File search

The original text is saved in a file. The agent can search the file with grep, like using Find in a document.

This keeps the source word-for-word outside the chat.

What “chunks” means

“Chunks” is not a special method. It just means we split a very long text into blocks because the agent interface is a chat.

Long source

A book, transcript, log, or benchmark context.

→

Split into blocks

Chunk 1, chunk 2, chunk 3, ...

→

Ask at the end

After all blocks are sent, we ask the question.

User: Context chunk 1/18: ...
Assistant: OK
User: Context chunk 2/18: ...
Assistant: OK
...
User: Now answer: Where is Mary?

At large sizes, the agent may compress earlier chunks. That is where exact facts can disappear.

The Mary example in plain English

Without file search

We paste the long text into the chat in many pieces. Later we ask: “Where is Mary?”

The sentence was in the original text, but the agent may answer:

Mary is not mentioned in the visible context.
Answer: unknown

Meaning: the fact did not survive in the agent’s usable memory.

With file search

We save the same original text as a file. The agent searches for “Mary”.

grep -n -i -C 2 'Mary' full_context.txt
→ Mary journeyed to the bathroom.

Meaning: the source file still has the exact sentence.

So is grep “smarter” than full context?

No. That is the wrong takeaway.

Grep is not doing deep reasoning. It is doing exact search. It works well when the question has a clear word to search for, like “Mary”.

Full context can still be better when the answer needs real reading, combining clues, counting many things, or understanding paraphrases.

What we can safely say now

Safe claims

Long agent chats can lose exact details.

Compression makes this worse because old text becomes a short summary.

Searching the original file can recover facts that the chat memory forgot.

The failure is not just one example; it appears across a 100-task mixed run.

Do not claim yet

Do not say grep beats true full context.

Do not say full-context models cannot retrieve needles.

Do not say grep is always better than reading.

Do not compare grep to “full context” unless the full context was truly uncompressed and lossless.

The clean experiment that settles the question

Run the same tasks in three ways:

Arm What the model gets What it answers from Why this arm matters
A. True full context The original source, word-for-word, small enough to fit. The model’s active view. This tests Paras’s point: full context should work.
B. Agent chat memory The source sent over many chat turns. Whatever the agent remembers after compression. This tests real long-running agent behavior.
C. File search The source saved as a file. Search results from the original file. This tests lossless external recall.

If C beats B, that means file search beats compressed chat memory. If C beats A, that would be the stronger and more surprising claim. We have not proven that yet.

Copy-paste verdict

We should be careful with the wording. The current result is not “grep beats true full context.” The current result is: when Codex is used like a long-running agent, the source is injected over many chat turns and old turns can be compressed. In that setting, exact facts can disappear from the agent’s usable memory. Grep helps because it searches the original source file word-for-word.

So the clean claim is: lossless file search can beat compressed agent memory. The missing control is a true no-compression full-context run on tasks small enough to fit. We should run three arms: true full context, turn-based compressed agent memory, and file+grep.
