CompactionBench

What do AI agents forget when their context gets compressed?

The problem

When an AI agent runs for too long, the conversation history exceeds the context window. The system compresses it to keep going.

But the agent still sounds confident. It just remembers the wrong thing.

Correct answer: Mary is in the bathroom.
Model answer: Mary moved around several rooms.

How it works

Step 1: Take a long text with a hidden question.
Step 2: Feed it chunk-by-chunk into Codex.
Step 3: Codex auto-compacts the conversation when it gets too long.
Step 4: Ask the question. Score the answer. Log what survived.

Benchmarks: BABILong (exact facts), OOLONG (aggregation), CLB (6 task types), SWE-chat (real coding sessions), Synthetic (controlled tests).

SWE-chat: too long, gives up, still wrong

1 million words of real coding conversation history.

Gives upAnswersCorrectness when it answers
Full conversation40%60%6%
Compressed and told what to find0%100%5%
Compression makes the model try harder but it still gets the answer wrong. Engagement goes from 60% to 100%. Correctness stays the same. The model becomes confidently wrong.

Can tools fix compaction loss?

Instead of giving the model the context, we gave it a file and told it to grep.

Task setRaw contextGrep the file
qa1 to qa1043%60%
qa11 to qa2083%90%
Grep beats context injection. The model is better at searching a file with a tool than finding the answer in a long injected context. Keeping original files accessible matters more than perfect compression.

CLB: different tasks, same pattern

6 types of coding tasks from Continual Learning Bench.

TaskClosenessWhat went wrong
Sales prediction24%Numbers close, not exact
Database queries16%Right query, wrong columns
Codebase fixes12%Described fix, gold is diff
Medical studies5%Wrong output format
Signal monitoring2%Text answer, gold structured
Poker0%Too little context
The model understands the task. It outputs answers differently than the gold expects. A format problem, not a memory problem.

Compression needs to know what matters

ConditionResult
Raw context3/5
Knows the question3/5
Task-type hint only~matches
Knows nothing0/5
Without knowing what you will ask, compression picks the wrong facts every time. A vague hint nearly matches knowing the exact question.

Task type determines the effect

TaskExampleResult
Who gave what to who"Who did Fred give the football to?"Easy. 100% correct.
Where is someone"Where is Mary?"Hard. Almost never correct.
Path finding"How does Mary get to the garden?"0% correct correct.
Counting events"How many job failures?"Compression destroys it.
Compaction is not one problem. Each task type fails differently. Some tasks are easy regardless. Some are hard. The interesting ones change with compression.

Failures are diagnosable

Failure typeExample
Fact dropped"Not specified in the context"
Wrong location"bedroom" instead of "bathroom"
Counting error"3" instead of "15"
Stale value"beta" instead of "epsilon"
Not just "the model got it wrong." Each failure type suggests a different fix.

Real tasks tell a different story

SWE-chat: At 1M tokens the model gives up 40% of the time. Compression drops that to 0%. But correctness stays at 6%. The model becomes confidently wrong.
CLB: Across 6 task types the model understands the task but cannot output in the format the gold expects. A format problem, not a memory problem.
BABILong: Some tasks are easy regardless of length. Some are hard. Some change with compression. The interesting ones are the ones that change.

What is next

Attention patterns: Why does the model drop certain facts? Inspect what open models attend to during compaction.
Gap metric: A single number researchers can use to diagnose their own systems.
Real-world testing: OOLONG-real, SWE-chat at scale, coding agent traces.
