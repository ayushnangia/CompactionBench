Is virtual context actually better than grep?

A step-by-step walkthrough of what the system does, what evidence we have, where it wins, where it fails, and whether the latest result could be a fluke.

fixed BABILong/OOLONG set1500 runspaired comparisonsmechanism exampleshonest caveats

Bottom line

It is not proven universally better than grep. But it is not just random noise either.

The evidence says: system-managed virtual context improves retrieval-heavy BABILong tasks because it extracts the right event trace and avoids carrier-text false matches. It does not solve OOLONG, where the missing piece is structured counting/aggregation.

Step-by-step: what happens in virtual context

1

Start with the same original source

For each task, the original task.context is unchanged. No answer key is used.

2

Split it into pages

The harness writes overlapping page files and a hidden index.

virtual_memory/
  pages/page_000001.txt
  pages/page_000002.txt
  page_index.jsonl
  manifest.json
3

Build a hidden page table

Each page has an id, file path, line range, token estimate, and preview. The model does not manage this table.

4

System memory kernel retrieves a resident set

BABILong uses a concise event extractor. OOLONG uses roll/spell/question-term windows. This happens before the model call.

5

Render the evidence packet

The model receives <VIRTUAL_CONTEXT_EVIDENCE>, not a pager tool and not one huge file.

6

Model answers with tools disabled

Virtual-context runs used 0 tool calls. The model just answers from the evidence packet.

Why this is better than grep when it works

  1. It removes memory-management burden from the model. The model does not choose search strings, inspect pages, or decide when to stop.
  2. It can structure the source before the model sees it. For BABILong, it turns noisy text into an event trace.
  3. It is auditable. Every virtual run records selected pages, item previews, evidence tokens, and strategy in metadata.
  4. It uses zero model tools. That matters for latency/control/reproducibility and for separating retrieval from reasoning.
  5. It provides a path to stronger systems. Add page-fault retries and structured operators; grep does not naturally become that.

Why it might still be a fluke

The total margin over grep is small. On all 250 tasks, relaxed score is only +2 to +2.4 points. Some bootstrap intervals include zero. So we should not claim “virtual context always beats grep.”

What we can say instead:

In this fixed BABILong/OOLONG run, transparent virtual context beat grep overall and showed a mechanism-consistent improvement on BABILong. The result is promising but not yet definitive; OOLONG needs structured aggregation.

How to make the evidence stronger next

  1. Do not rerun baselines. Reuse fixed-panel full_context/grep results.
  2. Run only corrected virtual variants. Larger sample, same fixed test set.
  3. Hard enforce evidence budgets. Current 8k/24k/48k labels were not strict enough.
  4. Add page-fault loop. Answer → verify support → retrieve more pages → retry.
  5. Add OOLONG table operators. Build roll/spell tables, then count/sort/filter deterministically.
  6. Report paired tests by dataset. Especially BABILong, where the mechanism should help.

Slack-ready summary

We tested whether virtual context is more than a grep replacement. On the fixed BABILong/OOLONG panel, system-managed virtual context beat grep overall (best strict 24.8% vs 20.8%; best relaxed 39.6% vs 37.2%) while using zero model tools. The win is concentrated on BABILong, where the memory kernel extracts clean event traces and avoids carrier-text false matches. OOLONG is still unsolved because it needs structured counting/aggregation, not just better retrieval. So: promising and mechanism-consistent, but not a universal “grep is beaten” claim yet.
