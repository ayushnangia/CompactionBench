Binary scoring says the model gets nothing right. Semantic scoring says it is partially correct on many tasks — the model understood the question but produced a different format than the gold expected.

This is not a compaction failure. It is a format mismatch. The gold answers are patches, SQL queries, and CSV predictions. The model often gives correct natural language explanations instead. Same problem we saw with BABILong where "Mary is in the bathroom" ≠ "bathroom."

Real example: database task
Text
QuestionHow many office product reviews have timestamps in 2031 or later?
Gold SQLSELECT COUNT(*) FROM fdbk_g1 WHERE ts > 1924992000 * 1000
Model SQLSELECT COUNT(*) FROM fdbk_g1 f JOIN products p ON p.product_id = f.product_id WHERE p.category = 'office' AND ...
Semantic scoreROUGE-L 51% · BLEU 14% · Keyword 50% → Combined 41%
The model clearly understood. It wrote a plausible SQL query joining the right tables. It just used different column names. A human reviewer would say "close, fix the column names." Binary scoring says 0%. Semantic scoring says 41%.
What this means
CLB tasks are code generation tasks, not fact retrieval tasks. They do not test compaction the way BABILong and OOLONG do. The model is creating new code, not extracting information from long context. This is a different benchmark, a different failure mode, and needs a different scoring approach.

The good news: all 6 task types are integrated, the pipeline works, and semantic scoring with ROUGE/BLEU gives a much more honest picture than binary exact match. The gap between binary 0% and semantic 16% is itself a finding — it tells us exactly how much of the "failure" is format mismatch vs genuine wrongness.
