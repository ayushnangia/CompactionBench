CompactionBench — Experiment Log

What happens when ~158,000 tokens of context are compressed into ~150?

Experiment 1: What does the compressor need to know?
A long context (~158k tokens) contains a multi-step update: "default model" changed from gpt-5.4-mini → gpt-5.3 → gpt-5.4 → claude-sonnet-4. The final confirmed value is "claude-sonnet-4". After compression to ~150 tokens, we test whether the compressed context still contains the answer. Three compression modes tested.
Input — Raw context (158,000 tokens, only signals shown) Initially, the default model was set to gpt-5.4-mini.
Then the team changed the default model to gpt-5.3.
Then the team changed the default model to gpt-5.4.

Finding: QB compresses filler because it has no relevance signal. QA preserves the answer because it knows the question. WH preserves the answer with only a task-type hint — it does not need the exact question.

Experiment 3: The Retention-Accuracy Gap
From 228 existing runs (BABILong qa1-10: 120 runs, OOLONG-synth: 108 runs). Measures how often the gold answer appears anywhere in the model's context vs how often the model actually gives the correct answer.
BenchmarkGold in contextCorrect answerGapInterpretation
BABILong qa1-1045.8%8.3%37.5ptModel has info but cannot use it
BABILong qa11-2041.9%14.7%27.2ptSimilar pattern
OOLONG-synth54.6%46.3%8.3ptModel uses what it has
Finding: BABILong asks for exact facts (names, places, objects). The model has the answer in context ~46% of the time but only answers correctly ~8% of the time. OOLONG asks for aggregation (counts, timelines). The model uses nearly everything it has. This gap is a diagnostic metric: large gap = exact memory failure, small gap = information is usable.

Finding: All compression conditions tied at 40% overall. But hiding inside that tie: task type determines whether compression helps, hurts, or does nothing. You cannot say "compression improves accuracy" without specifying the task.
Experiment 5: A smarter model cannot recover deleted information
15 scattered "job_failed" events in ~158k tokens. Task: count them (gold=15).
ModelConditionGuessesResult
gpt-5.4-miniRaw12, 14, 10, 9, 13Close range
gpt-5.4Raw15, 15, 15, 15, 15Perfect
gpt-5.4Compressed3, 3, 3, 3, 3Wrong
Finding: gpt-5.4 counts perfectly with full context. After compression, it guesses 3 instead of 15. The compressor deleted the events, and model intelligence cannot recover them. Information loss is final.
