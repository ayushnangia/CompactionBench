🔴 Fact dropped by compression (22 failures)
The compressor deleted the answer-bearing fact. The model knows it is missing and admits it.
FACT DROPPED
Q: Where is Mary?
bathroom → Not specified in the provided context.
Compressor selected filler sentences instead of the answer. Mary's location was lost.
FACT DROPPED
Q: How many objects is Mary carrying?
one → The context does not specify how many objects Mary is carrying.
The count fact was scattered across the context. Compressor missed it entirely.
Root cause: Query-blind compression has no signal for relevance. It selects facts by surface statistics (rarity, novelty). When the answer-bearing fact looks like filler, it gets dropped.
📍 Wrong location / entity (12 failures)
The model picks a place or person from the context — but the wrong one. Multiple locations/entities cause confusion.
WRONG LOCATION
Q: Where is Mary?
kitchen → bedroom
Multiple rooms mentioned. Model picked the wrong one. Classic entity confusion under long context.
WRONG LOCATION
Q: Where is Mary?
bathroom → bedroom
Same pattern. "bedroom" appears more often in the context. The model picks the most frequent location, not the correct one.
Root cause: The model preserves the general story ("Mary moved around rooms") but loses the exact location. This is the "keeps gist, loses state" failure mode.
🔢 Counting error (15 failures)
The model needs to aggregate many small scattered facts. Compression deletes most of them.
COUNTING ERROR
Q: How many job_failed events occurred?
15 → 3
Compressor kept 3 events out of 15. The model counts from what survived, not the original total.
COUNTING ERROR
Q: Is True more common than False?
more common than → True is less common than False
Binary aggregation flips under compression. With full context the model gets it right. Compressed: inverted.
Root cause: Counting requires broad coverage. Compression selects a few "important" facts and drops the rest. The model cannot count what it cannot see. A stronger model (gpt-5.4) counts perfectly with full context — 0% with compression.
🗣 Verbose but wrong fact (45 failures)
The model is confident and writes a full sentence — but gets the core fact wrong.
CONFIDENTLY WRONG
Q: Who did Fred give the football to?
Jeff → Cannot be determined from the provided context chunks.
Model admits it does not know. Better than hallucination, but still a failure. The fact was in the original context.
CONFIDENTLY WRONG
Q: What is the current deployment branch?
epsilon → beta
The value changed 4 times (alpha→beta→gamma→delta→epsilon). Model picked an intermediate value instead of the latest.
Root cause: Multi-step updates confuse the model. It remembers a value was mentioned but not that it was superseded. This is the "stale fact" failure mode — the model remembers an old value confidently.

Bottom line: Compaction failures are not random. They cluster into predictable categories: dropped facts (compressor missed it), confused entities (too many similar things), stale values (picked old version), and lost counts (needed broad coverage). This means the failures are diagnosable — not just "the model got it wrong."
