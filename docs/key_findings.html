CompactionBench

What happens when AI context gets too long and the system compresses it? Five findings from 648 Codex runs.

Finding 1
The Retention-Accuracy Gap
A metric that separates memory loss from reasoning failure. How often the answer exists in context vs how often the model actually gives it.

What this means: For exact-fact questions (Where is Mary? What object does she have?), the model has the answer in its context nearly half the time but can only retrieve it 8% of the time. For big-picture questions (counts, timelines, patterns), the model uses almost everything it has. Compaction destroys exact memory while preserving aggregate understanding.
Finding 2
QB vs QA vs Weak-Hint
Three ways to compress the same context. What does the compressor need to know to preserve the right information?

Input: Initially the model was gpt-5.4-mini. Changed to gpt-5.3. Changed to gpt-5.4. Final: claude-sonnet-4.
QB compressed: "Someone mentioned a VSCode extension..." ← kept filler
QA compressed: "After final review the model is now claude-sonnet-4" ← kept answer
WH compressed: "Final review the model is now claude-sonnet-4" ← also kept answer
What this means: You do not need the exact question. A task-type hint ("find the relevant value") is enough to guide compression. This matters for real agents because they do not know what question will be asked later — but they do know the task type. Weak-hint compression may be a practical path to better agent memory.

Finding 4
Failure Taxonomy
184 failures from 648 runs. Compaction failures are not random — they cluster into predictable categories.
CategoryCountExampleMechanism
Fact dropped22"Not specified in the context"Compressor missed the answer-bearing fact
Wrong location12"bedroom" instead of "bathroom"Multiple similar locations confuse
Counting error15"3" instead of "15"Compressor deleted events
Stale value45"beta" instead of "epsilon"Picked intermediate update
Other wrong90"a child" instead of "nothing"Could not locate fact
What this means: You can do a differential diagnosis on compaction failures. "Not specified" means the compressor dropped it. Wrong location means entity confusion. Wrong count means broad coverage was needed. Stale value means the model tracks updates poorly. Each failure type suggests a different fix.
Finding 5
Smarter Model ≠ Better Compaction
gpt-5.4 counts 15 scattered job_failed events perfectly with full context. After compression, 0% accuracy.

What this means: Intelligence cannot recover deleted information. The compressor kept 3 events and dropped the other 12. gpt-5.4 correctly counts the 3 it sees. This is not a reasoning failure — it is an information access failure. A more capable model gives the correct answer to the wrong question. This suggests future agent reliability depends more on compression quality than model capability.
