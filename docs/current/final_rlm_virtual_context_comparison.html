Long-context memory comparison

One final plain-English report comparing the older baselines, search + notes / virtual context, RLM depth-0, and full recursive RLM depth-1.

fixed real panel: 250 tasks 100 BABILong + 150 OOLONG-real all runs below are without compaction no baseline reruns

Short answer

Best exact / strict score

RLM depth-0

74/250. It helped most on exact BABILong lookups by letting the model write code over an external source.

Best relaxed score

Search + notes

99/250 for the 8k variant. This is the simple name for the older virtual_context arm.

Big surprise

Depth-1 lost

Full recursive RLM depth-1 was implemented and verified, but it was slower and less accurate: 47/250.

The two page methods, explained like a normal person

Model picks pages

Imagine a huge book split into many smaller page files.

  1. The model gets a page list.
  2. The model chooses which pages to open.
  3. The model reads those pages.
  4. Then it answers.

Problem: even when the setup is proper, the model can choose the wrong pages. If it opens the wrong pages, it misses the answer.

Search + notes

This is the easy name for virtual_context. Think of it as grep + note-taking.

  1. A helper does grep-like searching across many pieces of the source.
  2. The helper pulls out the useful lines.
  3. The helper turns those lines into short notes.
  4. The model only reads those notes and answers.

So it is basically: grep + note-taking + handing the model only the notes. The model itself does not use tools.

How each approach works and how it fails

Full context

works by putting everything in the prompt.

works when the answer is obvious and the model remembers the right details.

fails when the source is noisy. BABILong has carrier prose with misleading names like Mary in unrelated stories.

File grep

works by letting the agent search one file.

works when the answer has good keywords or exact phrases.

fails when the task asks for counting, first/last events, percentages, or combining facts across episodes.

Model picks pages

works by giving the model page tools and a page table.

works when the model chooses the right pages.

fails when the model searches the wrong pages or spends effort managing memory instead of answering.

Search + notes / virtual context

works by doing a grep-like search first, then making short notes for the model.

works when the useful lines are enough to answer, especially BABILong facts.

fails when the model still has to count or combine many events, especially OOLONG rolls and spells.

RLM depth-0

works by storing the source outside the prompt and letting the model write Python over it.

works when code search can find short, clear facts.

fails when the task needs judgment about what counts as a real D&D roll or spell event.

RLM depth-1 recursive

works by adding child RLM calls over pieces.

worked technically 250/250 tasks used child RLM calls after reruns.

failed empirically child RLMs often counted mentions rather than benchmark events, and runtime exploded.

What not to overclaim

Do not say “grep beats full context” as a universal claim. This benchmark shows that, on these fixed long real tasks and this model/settings, file search and search + notes often beat direct prompt stuffing.

Do not say recursive RLMs failed in general. What failed here was this specific depth-1 setup on BABILong/OOLONG. The RLM machinery worked; the child calls just did not learn what counts as a roll or spell in OOLONG.

Do not say search + notes is literally grep. It is grep-like search plus note-taking. The model itself uses zero tools.

Final takeaway

Best current recipe: use RLM depth-0 for exact external-memory code search, and use search + notes when you want fast, tool-free notes.

Next research step: OOLONG needs a dedicated roll/spell counter. Generic child RLM calls are not enough.

Shareable message draft

I finished the combined long-context memory report on the fixed real BABILong/OOLONG panel. Everything in this comparison is without compaction.

The main arms are: full context, file grep, model picks pages, search + notes (formerly virtual context), RLM depth-0, and full recursive RLM depth-1.

Search + notes means the helper program searches pieces first and gives the model short notes. It is like automatic multi-file grep, but the model itself uses 0 tools.

Results: RLM depth-0 had the best strict exact score, 74/250, mostly because it helped BABILong exact lookup. Search + notes had the best relaxed score, 99/250, and was much faster. Full recursive RLM depth-1 was implemented and verified with child RLM calls on every task, but it underperformed: 47/250 and about 220 seconds per task.

Takeaway: external code-over-context is useful for exact memory retrieval. Generic recursive child calls did not solve OOLONG counting. For OOLONG, the next step is a dedicated roll/spell counter, not just more recursion.
